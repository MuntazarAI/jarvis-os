# Getting help with JARVIS-OS

Thanks for exploring JARVIS-OS. Questions, feedback, and constructive criticism are welcome.

## Where to go

- **Something is broken:** open a [bug report](https://github.com/MuntazarAI/jarvis-os/issues/new?template=bug_report.md).
- **Have an idea or improvement:** use the [feature request template](https://github.com/MuntazarAI/jarvis-os/issues/new?template=feature_request.md).
- **Architecture or design question:** open an issue describing the use case, constraints, and alternatives, after checking existing issues.
- **Want to contribute:** start with [CONTRIBUTING.md](CONTRIBUTING.md), the [developer portal](docs/DEVELOPER_PORTAL.md), and the [roadmap](docs/ROADMAP.md).
- **Suspect a security vulnerability:** follow [SECURITY.md](SECURITY.md). Do not publish exploit details or secrets in a public issue.

## Before opening an issue

1. Search existing issues and pull requests for similar reports.
2. Include the smallest reproducible example, relevant logs, environment, and expected versus actual behavior.
3. Remove passwords, access tokens, personal data, private URLs, and other secrets from logs.
4. State clearly if a report is a question, a confirmed bug, a hypothesis, or a feature proposal.

## What to expect

JARVIS-OS is actively developed and may change. Maintainers and community members will try to respond constructively, but response times are not guaranteed. Not every proposal will be accepted; clear reasoning and respectful discussion help everyone understand decisions.
